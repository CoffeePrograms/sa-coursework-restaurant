# 6.1. Критерии готовности к разработке (DoR)

История берется в разработку, если:

<span id="dor-1"></span>DoR-1. История сформулирована по шаблону «Как …, я хочу …, чтобы …» и связана с бизнес-процессом раздела 1.

<span id="dor-2"></span>DoR-2. У истории есть критерии приемки в формате «Допустим — Когда — Тогда» с основанием: правило, ограничение или НФТ раздела 2.

<span id="dor-3"></span>DoR-3. Негативные сценарии отмечены в названии критерия.

<span id="dor-4"></span>DoR-4. Понятны данные: сущности и статусы истории есть в разделе 3.

<span id="dor-5"></span>DoR-5. Определены ресурсы API раздела 5 и экраны, если история меняет интерфейс.

<span id="dor-6"></span>DoR-6. Известны зависимости: внешние системы [раздела 4.3](../04-arhitektura/4.3-perechen-integraciy.md) и задачи других историй.

<span id="dor-7"></span>DoR-7. История разбита на задачи, каждый критерий приемки покрыт хотя бы одной задачей.

<span id="dor-8"></span>DoR-8. Для критериев с НФТ известны условия проверки: нагрузка [НФТ-03](../02-trebovaniya/2.4-nefunkcionalnye-trebovaniya.md#nft-03) «Нагрузочный профиль пилота» и выборка.
