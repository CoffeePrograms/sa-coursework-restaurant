{: #tablitsa-6-31 .caption }

| Критерий | Сценарий |
| --- | --- |
| <span id="us-16-ac-1"></span>AC-1. Заказ и оплата в приложении | Допустим торговый день открыт и приложение установлено на поддерживаемой версии ОС<br>Когда гость формирует корзину в приложении, выбирает способ получения и оплачивает заказ картой<br>Тогда заказ получает статус «Оплачен»<br>И заказ передается на кухню<br>И приложение показывает номер заказа<br>Основание: [ПР-19](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-19) «Заказ в мобильном приложении», [ПР-18](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-18) «Создание заказа», [ПР-16](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-16) «Номер заказа», [НФТ-14](../02-trebovaniya/2.4-nefunkcionalnye-trebovaniya.md#nft-14) «Поддерживаемые платформы» |
| <span id="us-16-ac-2"></span>AC-2. Цена по акции в приложении | Допустим на блюдо действует акция<br>Когда гость добавляет блюдо в корзину приложения<br>Тогда цена позиции рассчитывается по акции<br>Основание: [ПР-03](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-03) «Период действия акции», [ПР-19](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-19) «Заказ в мобильном приложении» |
| <span id="us-16-ac-3"></span>AC-3. Время отклика приложения | Допустим гость оформляет заказ в приложении<br>Когда гость добавляет позицию или меняет количество<br>Тогда приложение показывает результат не позднее 2с для 95% операций<br>Основание: [НФТ-12](../02-trebovaniya/2.4-nefunkcionalnye-trebovaniya.md#nft-12) «Время отклика приложения» |
| <span id="us-16-ac-4"></span>AC-4. Торговый день закрыт (негатив) | Допустим торговый день закрыт<br>Когда гость пытается оформить заказ в приложении<br>Тогда заказ не создается<br>И приложение сообщает, что новые заказы не принимаются<br>Основание: [ПР-17](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-17) «Прием заказов в открытый торговый день», [ПР-19](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-19) «Заказ в мобильном приложении» |
| <span id="us-16-ac-5"></span>AC-5. Электронный чек | Допустим гость оплачивает заказ в приложении<br>Когда платеж получает статус «Успешно»<br>Тогда облачная касса формирует электронный чек и отправляет его на e-mail, указанный гостем в приложении<br>И фискальные данные передаются в ОФД<br>Основание: [ПР-24](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-24) «Фискальный чек», [ПР-19](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-19) «Заказ в мобильном приложении» |
| <span id="us-16-ac-6"></span>AC-6. Не указан e-mail для чека (негатив) | Допустим гость оформляет заказ в приложении<br>Когда гость переходит к оплате без e-mail или с e-mail неверного формата<br>Тогда оплата не начинается<br>И приложение просит указать e-mail для электронного чека<br>Основание: [ПР-24](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-24) «Фискальный чек», [ПР-19](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-19) «Заказ в мобильном приложении» |
