# 3.3. Описание сущностей

В [таблице 3.1](#tablitsa-3-1) приведены сущности предметной области, их назначение, атрибуты, логические типы и ключи: первичный ключ (PK) и внешние ключи (FK) по связям [таблицы 3.2](3.4-svyazi-i-kratnost.md#tablitsa-3-2). Для перечислений указан тип enum и имя перечисления в [таблице 3.3](3.5-perechisleniya-i-statusnye-modeli.md#tablitsa-3-3). Денежные атрибуты содержат сумму в рублях с двумя знаками после точки, например «450.00». Идентификатор заказа уникален; номер заказа хранится отдельным атрибутом и уникален в пределах торгового дня.

**Пояснения:**

- Номер заказа уникален в пределах торгового дня (пример «A-042»).
- Номер заказа печатается на фискальном чеке и отдельным документом не хранится.
- Фискальный чек хранит реквизиты, по которым чек находят в ОФД: номер фискального накопителя, номер фискального документа и фискальный признак. Их заполняет фискальный регистратор или облачная касса, поэтому при статусе «Ошибка» они пустые. Остальные реквизиты чека (ИНН, адрес расчета, позиции) формирует фискальный регистратор или облачная касса из данных заказа, в модели они не повторяются.
- Фискальный чек связан либо с платежом (тип «Приход»), либо с возвратом (тип «Возврат прихода»). E-mail покупателя заполняется для электронного чека при оплате в мобильном приложении.
- Порядок передачи заказов на кухню по времени оплаты ([US-10](../06-zadachi/6.3-istorii-mvp.md#us-10) «Передача оплаченного заказа на кухню») определяется датой и временем успешного платежа; отдельный атрибут заказа не вводится.
- Атрибут «сотрудник» возврата — ссылка на учетную запись; сущность «Сотрудник» в модели не выделяется.
- Внесенная сумма и сдача при оплате наличными в модель не входят.
- «Дата и время» возврата — время последней попытки возврата.
