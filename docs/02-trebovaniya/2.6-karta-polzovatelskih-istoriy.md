# 2.6. Карта пользовательских историй

Карта построена по активностям пользователей и этапам пути. Для каждой истории указан выпуск: MVP — минимально жизнеспособный продукт, Релиз 1 или Релиз 2. Карта приведена в [таблице 2.4](#tablitsa-2-4).

Допущения: команда — 1 системный аналитик, 2 бэкенд-разработчика, 1 фронтенд-разработчик (киоск, табло, панель персонала), 1 мобильный разработчик на Релиз 1, 1 QA-инженер, 1 DevOps-инженер с частичной занятостью (общий с другими проектами), владелец продукта со стороны ресторана. Внешние системы уже работают и имеют API. Срок считается от старта разработки, закупка оборудования в него не входит.

MVP занимает не меньше 4 мес. из-за интеграций с оборудованием киоска и фискализацией. Максимальный срок учитывает риски: задержку доступа к API внешних систем, настройку кассы, доработки после испытаний на кухне. Релиз 1 частично можно вести параллельно с пилотом.
