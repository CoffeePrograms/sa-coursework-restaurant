# 5.2. Контракт метода POST /orders

Метод создает заказ из корзины, когда гость переходит к оплате ([US-04](../06-zadachi/6.3-istorii-mvp.md#us-04) «Проверка корзины», [AC-4](../06-zadachi/6.3-istorii-mvp.md#us-04-ac-4)). Сервис заказов проверяет статус торгового дня, состав и наличие позиций, рассчитывает сумму по актуальным ценам Сервиса меню и создает заказ в статусе «Создан». Цена за порцию, скидка, наценки, акция и модификаторы фиксируются в позициях заказа ([ПР-05](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-05) «Фиксация цены при создании заказа»). Номер заказа в ответе пустой: он присваивается при оплате ([ПР-16](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-16) «Номер заказа»). Параметры вызова приведены в [таблице 5.2](#tablitsa-5-2), поля запроса — в [таблице 5.3](#tablitsa-5-3), поля ответа — в [таблице 5.4](#tablitsa-5-4), ошибки — в [таблице 5.5](#tablitsa-5-5).

Таблица 5.2 — Параметры вызова POST /orders
{: #tablitsa-5-2 .caption }

| Параметр | Значение |
| --- | --- |
| Метод | POST |
| URL | /api/v1/orders |
| Аутентификация | Токен киоска или токен гостя в мобильном приложении |
| Заголовок Idempotency-Key | Обязателен: UUID попытки создания заказа |

Таблица 5.3 — Поля запроса POST /orders
{: #tablitsa-5-3 .caption }

| Поле | Тип | Обяз. | Описание |
| --- | --- | --- | --- |
| receiveType | string | да | «В зале» или «С собой» ([ПР-18](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-18) «Создание заказа») |
| loyaltyId | string | нет | Идентификатор гостя во внешней системе лояльности; без него заказ анонимный ([ПР-07](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-07) «Идентификация по QR и анонимный заказ») |
| expectedTotal | string | нет | Сумма, которую клиент показал гостю при проверке корзины |
| items | array | да | Позиции заказа, не менее одной |
| items\[\].dishId | uuid | да | ID блюда |
| items\[\].quantity | integer | да | Количество, не менее 1 |
| items\[\].modifiers | array | нет | Изменения состава блюда |
| items\[\].modifiers\[\].ingredientId | uuid | да | ID ингредиента из состава блюда |
| items\[\].modifiers\[\].action | string | да | «Исключен» или «Добавлен» |

Пример запроса:

```json
{
  "receiveType": "В зале",
  "loyaltyId": "LY-00012345",
  "expectedTotal": "858.00",
  "items": [
    {
      "dishId": "3f1c2a10-7b5e-4c1d-9a2b-1e2f3a4b5c6d",
      "quantity": 2,
      "modifiers": [
        {"ingredientId": "c1a2b3c4-0000-4a1b-8c2d-000000000001", "action": "Добавлен"},
        {"ingredientId": "c1a2b3c4-0000-4a1b-8c2d-000000000002", "action": "Исключен"}
      ]
    },
    {
      "dishId": "8a7b6c5d-4e3f-4a1b-8c2d-9e0f1a2b3c4d",
      "quantity": 2
    }
  ]
}
```

Таблица 5.4 — Поля ответа 201 Created
{: #tablitsa-5-4 .caption }

| Поле | Тип | Описание |
| --- | --- | --- |
| orderId | uuid | ID заказа |
| number | string | Номер заказа, до оплаты пустой |
| status | string | «Создан» |
| receiveType | string | Способ получения |
| loyaltyId | string | Идентификатор гостя, если передан |
| items\[\].itemId | uuid | ID позиции заказа |
| items\[\].dishId, items\[\].name | uuid, string | Блюдо и его название на момент заказа |
| items\[\].quantity | integer | Количество |
| items\[\].unitPrice | string | Цена за порцию: цена меню или цена по акции плюс наценки за порцию |
| items\[\].discountAmount | string | Сумма скидки по позиции |
| items\[\].surchargeAmount | string | Сумма наценок по позиции |
| items\[\].amount | string | Сумма по позиции |
| items\[\].promotionId | string | Примененная акция, пустое значение — без акции |
| items\[\].modifiers\[\] | array | Модификаторы: ingredientId, name, action, surcharge |
| total | string | Сумма к оплате |
| createdAt, statusChangedAt | date-time | Дата и время создания и изменения статуса |

  "number": null,
  "status": "Создан",
  "receiveType": "В зале",
  "loyaltyId": "LY-00012345",
  "items": [
    {
      "itemId": "0f9e8d7c-1111-4b3c-9d8e-000000000001",
      "dishId": "3f1c2a10-7b5e-4c1d-9a2b-1e2f3a4b5c6d",
      "name": "Бургер классический",
      "quantity": 2,
      "unitPrice": "369.00",
      "discountAmount": "0.00",

    {

Таблица 5.5 — Ошибки POST /orders
{: #tablitsa-5-5 .caption }

| HTTP | Код | Когда |
| --- | --- | --- |
| 400 | VALIDATION\_ERROR | Нет позиций или способа получения, неверный формат поля ([ПР-18](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-18) «Создание заказа») |
| 401 | UNAUTHORIZED | Нет токена или токен неверный |
| 409 | TRADING\_DAY\_CLOSED | Торговый день закрыт ([ПР-17](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-17) «Прием заказов в открытый торговый день») |
| 409 | TOTAL\_CHANGED | Рассчитанная сумма отличается от expectedTotal, например истекла акция; ответ содержит пересчитанные позиции ([ПР-04](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-04) «Истечение акции до создания заказа») |
| 409 | IDEMPOTENCY\_CONFLICT | Ключ уже использован с другим телом запроса |
| 422 | DISH\_NOT\_AVAILABLE | Блюдо или добавка без признака «В продаже» ([ПР-05](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-05) «Фиксация цены при создании заказа») |
| 422 | MODIFIER\_NOT\_ALLOWED | Ингредиента нет в составе блюда или изменение запрещено ([ПР-02](../02-trebovaniya/2.3-ogranicheniya-i-pravila.md#pr-02) «Состав блюда и наценки») |
| 500 | INTERNAL\_ERROR | Внутренняя ошибка |
| 503 | DEPENDENCY\_UNAVAILABLE | Недоступен Сервис меню или Сервис торгового дня |

Повторный запрос с тем же Idempotency-Key и тем же телом возвращает 200 OK и ранее созданный заказ.
